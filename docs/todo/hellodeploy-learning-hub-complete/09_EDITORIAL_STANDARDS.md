# Editorial Quality and Publishing Standards

## Reader value
Original, accurate, task-completing education for students, beginner developers, freelancers and operators. Readers should be able to apply steps without creating a HelloDeploy account. Mention product only where relevant, distinguish platform-specific behavior from generic deployment guidance.

## Article pattern
Accurate H1 and deck; problem/context; what reader learns; prerequisites; numbered implementation or decision framework; clearly labeled commands and expected outcomes; troubleshooting; security and limitations; meaningful FAQ where warranted; references to primary documentation; actual tested environment and verified date when tested; related guides; genuine author profile. Word count is not a ranking rule; 1,200–2,000 words is a planning range only.

## Fact checking
Verify all CLI flags/version support from current authoritative docs; test code in safe disposable environment when feasible; do not invent benchmark, pricing, screenshots, or empirical results; label illustrative configuration distinctly. For potentially dangerous server commands explain context and backup path. Source current comparisons and any changing product details. Prefer original diagrams/screenshots, ensure attribution/license and alt text. Avoid generic filler and exaggerated claims.

## Editorial workflow
Draft → technical check → fact/source check → copy edit → SEO check → publication. Document review evidence in commit/PR; updatedAt only when substantive revision. Add scheduled reevaluation for version-sensitive tutorials, broken links, obsolete steps and reader-reported problems.

## Author transparency
Use truthful author name, credentials and editorial responsibility. No fictional user comments, fake view counts, manufactured testimonials or invented testing environments.
