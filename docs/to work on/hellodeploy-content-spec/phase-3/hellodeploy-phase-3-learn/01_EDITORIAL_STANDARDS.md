# Phase 3 Editorial Standards

## Reader Profile

Primary readers include:

- beginner developers
- students
- freelancers
- educators
- small business website owners
- developers new to deployment

## Writing Standard

Explain the simple version first.

Then add technical detail.

Use short paragraphs and concrete examples.

Avoid:

- generic marketing language
- exaggerated claims
- unnecessary jargon
- article padding
- repetitive definitions
- keyword stuffing
- fake statistics
- fake quotes
- fake case studies

## Article Structure

Use this structure when useful:

1. Introduction
2. What it means
3. How it works
4. Why it matters
5. Example
6. Common mistakes
7. HelloDeploy connection
8. FAQ
9. Related guides

Do not force every section.

## Search Intent Rule

Each article should answer the exact user intent behind the title.

Example:

Title:

```text
What Is a VPS?
```

The reader likely wants:

- definition
- how it differs from shared hosting
- what resources it provides
- when it is useful
- whether they need one

Do not turn the article into a HelloDeploy sales page.

## Originality Rule

Prefer examples from actual HelloDeploy development and deployments.

Use:

- real deployment screenshots
- real DNS examples
- real logs after sanitization
- architecture diagrams
- lessons learned
- real project case references

## Product Linking Rule

A HelloDeploy CTA is appropriate only when it follows naturally from the topic.

Example:

A DNS article can link to:

```text
/docs/custom-domain
```

A build command article can link to:

```text
/docs/build-configuration
```

Do not force a CTA into every section.
