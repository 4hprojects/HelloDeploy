# Troubleshooting Escalation and Support

## Purpose

Define when self-service troubleshooting should transition to support.

## Contact Support When

The user has verified:

- project configuration
- build command
- start command
- environment variables
- application port
- deployment logs
- domain and DNS where relevant

and the problem still appears to be HelloDeploy platform behavior.

## Information to Include

Ask users to provide:

- project name
- deployment ID
- approximate time of failure
- runtime or framework
- relevant error text
- steps already tried
- screenshot if useful

## Never Request

- passwords
- API keys
- private keys
- database passwords
- deploy hook URLs
- OAuth client secrets
- service role keys

## Support Categories

Suggested:

- deployment failure
- runtime issue
- domain/DNS
- HTTPS
- account issue
- billing
- suspected platform bug

## Incident Pattern

If multiple unrelated users report the same platform-level issue, consider linking to the status page.

Do not label an event an outage unless confirmed.
