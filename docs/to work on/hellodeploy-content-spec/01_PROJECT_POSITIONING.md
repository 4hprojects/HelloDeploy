# HelloDeploy Project Positioning

## Primary Positioning

HelloDeploy is a deployment platform that helps users publish and manage supported web applications without manually handling every server administration task.

### Primary Statement

> Deploy your website without managing the server.

### Supporting Statement

> HelloDeploy provides a guided way to configure, deploy, connect domains, manage environment variables, review deployment logs, and publish supported web applications from one place.

## Target Users

HelloDeploy should speak clearly to:

- students
- beginner developers
- freelance developers
- educators
- small teams
- small businesses
- website owners
- developers who want a simpler deployment workflow

## Positioning Principles

HelloDeploy should feel:

- practical
- understandable
- transparent
- beginner-friendly without being simplistic
- useful to developers without requiring DevOps expertise

Avoid generic claims such as:

- revolutionary hosting
- deploy anything
- unlimited everything
- zero configuration for every framework
- enterprise-grade by default

## Runtime Positioning Rule

Do not describe HelloDeploy as Node.js-only unless that is intentionally the product scope.

Do not claim support for runtimes that have not been tested.

Preferred wording:

- supported web applications
- supported runtimes
- supported deployment configurations
- compatible frameworks

Avoid:

- deploy any backend
- deploy all programming languages
- universal deployment
- every framework supported
