# HelloDeploy Phase 2: Documentation Overview

## Purpose

Phase 2 builds the public HelloDeploy documentation. The documentation must explain how to use HelloDeploy without requiring direct support.

## Main Goal

The documentation should help a user answer:

- How do I create a project?
- What deployment settings do I need?
- What is a build command?
- What is a start command?
- How do I configure environment variables?
- How do I connect a domain?
- What is a deploy hook?
- Where do I read deployment logs?
- How do I redeploy a project?
- What should I check when deployment fails?

## Documentation vs Learn Content

Documentation answers: How do I use HelloDeploy?

Learn content answers: How does this deployment concept work?

Example:

- Documentation: How to Add Environment Variables in HelloDeploy
- Learn: What Are Environment Variables?

## Global Rules

Every documentation page should:

- explain one clear task or concept
- be usable without contacting support
- use actual HelloDeploy labels where possible
- avoid inventing UI that does not exist
- avoid claiming features that are not implemented
- include expected results
- include common mistakes
- link to related documentation
- use screenshots where they add value
- hide sensitive values in screenshots
- work well on desktop and mobile

If a page describes an existing UI flow, verify exact labels and behavior before publishing.
