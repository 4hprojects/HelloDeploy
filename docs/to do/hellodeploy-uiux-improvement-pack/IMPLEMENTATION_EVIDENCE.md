# UI/UX Improvement Program — Repository Implementation Evidence

Updated: 2026-10-02

## Repository-local status

The six ordered implementation batches are represented in the repository. They add
the shared status/measurement contracts, public discovery routes, guided onboarding,
project discovery, polling deployment workflows, operational admin views, hashed
assets, accessibility/responsive corrections, deterministic browser QA, sanitized
captures, and lab budgets described by this pack.

The implementation remains server-rendered Express/EJS with progressive enhancement.
It does not grant the web process Docker access or change stored secret formats.

## Evidence boundaries

- Product and social previews are generated by `npm run previews:capture` from the
  real app and deterministic synthetic records. No production data is used.
- Playwright/axe and Lighthouse use that same fixture and are local lab evidence.
- The `ProductEvent` collection accepts allowlisted events/properties only and has a
  90-day TTL. Installation verification checks the index without reading events.
- Production release identity uses a root-written metadata artifact; the web process
  only reads and displays its expected/actual SHA state.
- Production, supported-host Docker, external DNS/crawler, real-device, authorized
  deployment, and five-user usability gates are not claimed by repository fixtures.

## Commands

The required repository-local gate is:

```sh
npm run assets:build
npm run assets:verify
npm run assets:budget
npm run lint
npm run format:check
npm run config:check
npm test
npm run test:browser
npm run performance:lab
npm audit --omit=dev --audit-level=moderate
git diff --check
```

After a separately authorized release, run `npm run production:check -- --expected-sha
<full-sha>` and the authenticated/admin, supported-host, DNS, TLS, and screenshot
checks before recording any production completion.
